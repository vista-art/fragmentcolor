# AGENTS.md — Shader rules (short)

Ownership & validation
- `Shader` owns `Mesh` attachments; validate at attach time and reject incompatible meshes with a typed `ShaderError`.
- No invalid mesh may be attached to a shader under any circumstance.
- If the shader has no `@location` vertex inputs (fullscreen / builtin-only), attaching a mesh must be rejected.
- `reflect_vertex_inputs` is the one list of vertex inputs. It holds each `@location` argument of the vertex entry point and each `@location` member of a struct argument, under the member's name, so `bind_mesh`, the renderer's vertex layouts and its no-mesh check read struct members as they read arguments. A struct of built-ins only adds nothing and stays a fullscreen input.
- Attach checks every vertex and instance value, not only the first, and each one must hold every attribute the shader reads. A failed attach records nothing on the mesh, so `Pass::add_mesh` can try the next shader.
- `bind_mesh` returns a `Binding`: the types it gives untyped attributes and the attributes it reads, with their formats. `MeshObject::declare` keeps the types for the mesh's lifetime and the reads under the shader's `id`, so a vertex or instance added later holds what each attached shader reads. `remove_mesh`, `clear_meshes` and dropping the shader (`Drop`) take its reads off the mesh.
- A vertex that sets a property named `position` fails the attach with `ShaderError::InvalidKey` (`check_position`), since its position comes from `Vertex::new`.

Constructors
- `Shader::new(source: &str) -> Result<Self, ShaderError>` — WGSL or GLSL source; the core Rust entry point.
- `Shader::from_mesh(mesh: &Mesh) -> Result<Self, ShaderError>` infers a minimal shader from a mesh's first vertex and attaches the mesh. An empty mesh returns `InvalidKey`, and a mesh the shader refuses returns the attach error.
- `Shader::from_vertex(v: &Vertex) -> Result<Self, ShaderError>` builds the same shader from one vertex: the position at `@location(0)`, and a `color` of four numbers at `@location(1)`, read by name.
- The mesh quick view (`Renderable for Mesh`) draws on the mesh's own pass, which holds the mesh (`PassObject::for_mesh`). `plan_pass` builds its shader there (`ensure_preview`, `MeshObject::preview_in`) once the mesh has a vertex, whatever reached the pass, so a mesh a pass required while empty draws once it has vertices. It reads the first vertex only to build the shader, once, in a statement of its own, so no vertex guard is held while the shader compiles or checks the vertices. Its shader (`preview`) checks the mesh whenever the mesh changed, holds it while it passes and lets it go while it fails, and records types but no reads. Each check that passes records its types (`hold`), a held mesh included, so a type a later check finds, such as a `color` it now reads from an instance, stays as a first check's does. `plan_shader` runs that check on every render of the shader, whatever reached its pass, `render(mesh)` or a `Pass::require` of the mesh, in one step with its read of the mesh list (`read_meshes`), so a check on another thread can't let the mesh go between the two. It draws an upload of the quick view's mesh only when the mesh's generation stayed where the check passed until the upload ended (`upload_checked`). Otherwise it checks and uploads again, `PREVIEW_TRIES` times at most, and then returns `MeshError::Busy`. A refused mesh returns the check's error on every render, in place of the error for a shader with no mesh.
- An attach (`record`) holds the shader's mesh list from `declare` to the push. A `Model` attach goes through `attach_model`, which attaches a mesh once and assumes the Model columns for a mesh with no instance layout.
- Mobile uniffi: `Shader::new_mobile(source: String) -> Result<Arc<Self>, FragmentColorError>` in `platform/mobile.rs` (owned `String` + `Arc<Self>` as uniffi requires). Swift / Kotlin extensions re-expose it as `Shader(source)`.

Creation checks (`Shader::wgsl`, which every constructor reaches)
- Parse and validate with `create_validator` / `create_parser`: the naga capabilities of `CANDIDATES` (`core/renderer/device.rs`), the features a device may open with. A shader that needs another feature (`f16`, `primitive_index`, subgroups, `texture_external`, texture atomics) fails here, never at render.
- `parse_uniforms` refuses two globals on one `@group`/`@binding` (`claim_slot`) and writable storage that a `@vertex` entry point uses. It records each global's `Uniform::stages` from naga's `ModuleInfo`; the renderer makes each binding visible to those stages, and a global no entry point uses to the compute stage.
- `immediates::check_immediates` lowers the immediate roots to uniforms on a copy and validates it, since the web and devices without immediates bind them that way. `lower_immediates` is the one rewrite, shared with the renderer.
- `struct_layouts::write_layouts` writes the WGSL the browser's WebGPU gets for a module whose buffer structs set `@size`/`@align`: naga's own writer output for the unchanged module, with a `@size` on each member of a pinned struct but a runtime-sized array. FragmentColor renames nothing: `name_pinned` runs naga's namer as the writer sets it up and finds each pinned struct under the name it gives, and `name_entries` gives the entry point names the browser's pipelines ask for. It reads the text back and refuses a struct whose layout moved. Only the renderer calls it, on the browser's WebGPU, so `Shader::new` never refuses a shader because of the web's text. `list_explicit` names those structs for the GL refusal.
- `check_samplers` refuses a filtering `sampler` that samples a depth texture, which the web refuses. A light root still claims its slot in `parse_uniforms`, so a global on it fails as two globals on one slot do.
- A texture uniform set from a source (`set_map`, which the Material's lazy setters and the glTF loader reach) is a map (`uniforms/texture_maps.rs`): the shader keeps the source in a `TextureMap`, and nothing drains it. The key takes one `TextureId` when it becomes a map and keeps it while it stays one, and the slot names that id from the setter call on. Each setter call takes a new stamp. `Renderer::load` uploads a copy into each context that lacks one or holds one from an older stamp, and `keep_upload` compares stamps under `maps.write()` (`TextureMap::takes`): it keeps an upload of the latest source, or an older one while the context holds no copy or an even older one, and never lets an older upload replace a newer copy. An overtaken upload stands in, and the next load uploads the latest, so the latest call wins across an `.await` and a stream of sets can't leave a context without a copy. The map records each context that holds a copy (`Upload`, by `RenderContext::id` with a `Weak`), and its `Drop` frees every copy still alive.
- A texture key is in `maps` or in `bound_textures`, never both. An explicit texture ends the key's map (`remove_map`), unless its id is the map's own, as when a `get` comes back through `set`. A map's id binds only its own slot: both write paths run `check_bind`, which refuses a live map's id (`LIVE` in `uniforms/texture_maps.rs`) on any other key with `ShaderError::ForeignMap` before the slot changes. A texture write with id 0 unsets the key on both write paths: the slot names 0 and the key keeps neither a map nor a bound texture, so a PBR slot draws its default. `set_map` checks the key against the storage before it takes `texture_writes`, since a flush holds the storage while it waits for that lock. Replaced sources, maps and registrations drop after the locks.
- `reflect_vertex_inputs` runs once at creation and refuses two inputs with one name.
- Raw bytes for a storage or immediate root must be exactly its size (`UniformInput::resolve`, `set_storage_bytes`, `set_push_bytes`).
- Array elements get no keys of their own; `locate_key` resolves `u.items[2].v` by walking the shape.

Reflection & mapping
- Vertex input mapping order (`mesh_attach.rs` and `Renderer::vertex_buffer_layouts` follow the same one):
  1. by name, instance first, then vertex (`position` included)
  2. position at location 0
  3. by the mesh's own buffer location, instance first, then vertex
- Typed Rust values (`f32`, `u32`) must match exactly. Plain numbers take the declared type: floats, or integers when every value is whole and in range. A misfit is an `AttributeMismatch` naming the attribute, the declared type and the value.
- The first shader that reads an untyped attribute fixes its type for the mesh. A shader that declares another type fails to attach with `AttributeConflict`, whatever value the mesh holds now.
- Every pipeline compiles from a naga module. On the browser's WebGPU, wgpu writes it back to WGSL, which drops `@size` and `@align`, so a module with explicit layouts goes as `write_layouts` text there. The GL backends write a std140 block member by member and refuse such a layout. Built-in WGSL spells its padding out as members, as `PbrMaterial` and `TextureUv` do, which every backend keeps, and `pbr_layout_survives_the_web_round_trip` checks the PBR layouts through the WGSL round trip.
- On a backend that pads uniform bindings to 16 bytes (GL, WebGL2), `pad_uniform_blocks` pads immediate roots too, and the renderer always lowers them there, so a lowered root binds a multiple of 16 bytes.

Light roots (`lights/roots.rs`, `lights/mod.rs`)
- `lights` and `light_grid` are reserved root names in a module with a vertex or fragment entry. `Shader::new` recognizes them before `parse_uniforms`: the read-only storage `Lights` (with an optional `var<storage, read> light_grid: array<u32>`) or the older uniform `LightArray` of `N` lights. Matched roots leave `UniformStorage`, `list_uniforms`, `list_keys` and the storage registry; the renderer fills them.
- A storage `lights` or a `light_grid` with another layout fails with `ShaderError::TypeMismatch` that spells out the layout. A uniform `lights` that matches neither shape stays a plain uniform and logs one warning. Compute-only modules are never checked.
- `set` and `get` on `lights.ambient` reach the shader's ambient term; every other `lights.*` key is `UniformNotFound`.
- A lit shader keeps a weak, deduplicated list of the lights that reach it, in attach order. Passes and scenes hold the lights. Every list or ambient change, every light setter and every light drop bumps the light epoch, which tells the renderer to repack.
- On the uniform light path, `lower_module` lowers the storage roots, after padding: `lights` becomes a uniform block of the device's light count and `light_grid` a private word. `Renderer::render` refuses a shader that calls `arrayLength` on a root there with `FeatureError` and keeps that verdict, so `lower_roots` meets one only as a backstop, which returns `TypeMismatch`. The lowered modules are cached per light count and padding.

Errors & API shape
- Return `ShaderError` from shader APIs; avoid `unwrap` / `expect` / `panic`.
- `set()` never waits for the storage, so it never waits for a draw: it queues a last-wins update when the storage is busy. A texture value or a new map waits on `texture_writes` while the shader binds another texture, makes another map, or `flush_pending` applies its queue. Neither waits on the GPU. Reads block on the storage's read lock, which a `set` holds only for its write, so a read never fails under contention.
- Keep public methods thin; delegate to internal state.
- `UniformData` and the shapes it holds (`ArrayElement`, `StructShape`, `StructField`, `StorageEntry`, `StorageAccess`, `PushEntry`) are crate root exports with no docs/api page. They are the plumbing behind `Shader::set`'s `impl Into<UniformData>` and `Shader::get`, as `ShaderInput` is for `Shader::new`, so a Rust helper can forward one value to several shaders. Being root exports, they need no `type` line in docs/api/PARITY for the mobile classes of the same names.
