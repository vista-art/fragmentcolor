# AGENTS.md — Renderer rules (short)

Core invariants
- Draw all meshes attached to a Shader under the same RenderPipeline (per-shader batching).
- Pipeline cache keys are descriptive structs, not tuples:
  - `RenderPipelineKey { shader_hash, color_format, depth, sample_count, alpha_mode, double_sided, vertex_layouts }`, where `depth` is a `DepthUse` (`src/renderer/depth.rs`)
  - `ComputePipelineKey { shader_hash, bind_group_entries }` (layout entry contents, never resource addresses)
  Do not rely on tuple ordering; extend these structs if new state starts to affect pipeline configuration.
- If a shader has no `@location` vertex inputs, draw a single fullscreen triangle (three built-in verts). A shader that reads `@location` inputs and has no mesh returns `ShaderError::InvalidKey` naming the first one, before any pipeline is built. The inputs come from `reflect_vertex_inputs`, which flattens the `@location` members of struct arguments, so the layouts and this check treat a member like an argument.
- Vertex layouts are derived from the shader's first mesh and are part of the pipeline key, since shaders with the same source can feed meshes with different layouts. The renderer does not re-validate per-mesh at draw time.
- A mesh with an empty index list draws nothing.
- A shader that draws any of the pass's Models, hidden ones included, skips a mesh that gets instances only from Models (`MeshObject::awaits_models`) when no visible Model in the pass draws it through that shader. The pass's Model buffers are keyed by (shader, mesh), so another shader's visible Model on the same mesh doesn't count. That covers a hidden Model and a Model added to another pass through a shared Material. Drawing it would read whatever buffer an earlier mesh left in slot 1. Every other draw goes on: the same mesh in a shader of its own or in the quick view, and a mesh with instances of its own, even instances without properties.
- When no Model drives the draw and the pipeline reads instance attributes, a mesh draws no more instances than it holds, and a larger count returns `MeshError::InvalidInstance`. That covers a `set_instance_count` past the instances, and a shader that reads the Model columns for a Model's mesh while drawing no Model in the pass, whose message names the columns it reads (`name_columns`). A pipeline that reads no instance attribute draws any count, from instances without properties too.

Error scopes & the pipeline cache
- `RenderContext::validate(label, op)` is the one place GPU work runs in error scopes. It pushes one scope per filter in `SCOPES` (out of memory, internal, validation) and pops them in reverse order on every path, `op`'s own errors included. Of what they catch, `Caught::split` takes the cause in that order, since running out of memory or an internal failure leaves an object whose next use fails validation. The errors it leaves go to the log. `SCOPES` pairs each filter with the `ErrorKind` its errors report (out of memory is `Memory`), and `Caught::split` tags each error with the kind of the scope that caught it. On native the cause returns from that call as `RendererError::DeviceError { kind, label, .. }`.
- On native, `scope::Origin` records per thread where `op`'s error came from. When it came from the GPU (a nested scope caught it, or the surface failed validation and sent its details to the device), the cause the outer scopes caught came first, and it returns under the outer label. A CPU error from `op` wins, whatever its variant, and the GPU error goes to the log as a warning. On wasm `op`'s own result always returns, and `ErrorSlot::watch` logs the scope's errors at error level when they land, storing none of them when `op` failed.
- Pipeline builds and the frame use `validate`. A step inside a frame (a bind group, a texture view) uses `validate_step`, which scopes it on native so its error keeps the step's label, and runs it bare on wasm, where the frame's scopes cover it.
- Each render and compute pipeline comes from `fetch_pipeline`, which builds a miss inside `validate_with` and inserts only what built, so on native a pipeline that failed is never cached and the next frame reports the same error.
- Each frame records its passes and submits them inside one `validate("frame", ..)`. `submit` calls `plan_pass` for every render pass before `acquire_frame`. It checks the light cap (`check_light_cap`), builds the pass's Model buffers (`build_pass_draws`), and decides each shader's layouts (`read_layouts`) and each mesh's buffers and instances (`pick_instances`). The CPU checks that need no frame run there (a lit shader past the light cap, a shader that reads vertex inputs with no mesh, a mesh asked for more instances than it holds), so those errors acquire no frame, and the draw loop draws from the plan without deciding again. A frame that was acquired is presented on every path, failed ones included: Vulkan takes an acquired image back only through a present, and dropping it leaks a swapchain image. wgpu clears an image that no valid submit drew into. On Apple the encoder is submitted before each compute pass that follows another, so a pass after that split that fails leaves what the earlier submit drew.
- On wasm a scope resolves after `render` returns. `validate` hands the popped scopes to `ErrorSlot::watch` (`late.rs`). Each error that lands goes to `log::error!`, a `console.error` that the web healthcheck fails on outside its `late_errors` module, and the first one waits in `RenderContext::late`. `render` takes it before any GPU work. `load`, `read_storage` and `read_texture` call `ErrorSlot::settle` first, and so does `read_pixels`, which both `get_image` call. `read_texture` settles and then calls `copy_pixels`, so it settles once. `settle` waits until every scope opened before the call has landed. The slot keeps the ticket of the scope that stored its error, and `settle` takes the error only when that ticket comes before the call, so an error from a frame rendered while it waits stays for the next call. `render` takes whatever waits, since every stored error landed before it was called. Only the first error that lands while the slot is empty is returned, once. One that lands while another waits only logs, and a readback whose error another call took first returns its bytes.
- On wasm a pipeline's error lands after the insert, so the failed pipeline stays cached until then, and frames that use it meanwhile report a frame error. When the error lands, `validate_with` runs an eviction, so the next frame that draws with it builds it again and reports the same error. In a loop that renders each frame, the `render` right after the error landed throws it before any work, and the one after that builds the pipeline again. A check that has to fail in the same call on the web runs on the CPU before any wgpu call.

Depth
- `RenderContext::resolve_depth` picks each render pass's depth attachment. A depth target the pass set wins, and its sample count must match the color attachment (`DepthSampleCountMismatch`). Otherwise a pass with Models takes a pooled `Depth32Float` sized and sampled like its color attachment, cleared to 1.0 and discarded at the end. Any other pass draws without depth, in order.
- In a pass that draws Models, a shader that draws none of them (a fullscreen backdrop, an overlay mesh) uses `DepthUse::Ignore`, with the pooled depth or a depth target the pass set: it passes every fragment and writes no depth, so it draws in order and hides no model. In a pass without Models, an explicit depth target makes every shader test depth. Every pipeline in a pass declares the attachment's format, so ignoring depth is a pipeline state, never a missing attachment.
- A render pass takes its size from `TargetFrame::size`, never `Target::size`. A resize can land between acquiring the frame and drawing, and every attachment must match the frame.
- Blend draws test depth and never write it.

Render targets & present
- If no per-pass offscreen target is set, render to the provided final frame by default.
- Per-pass targets render intermediate results; the last render pass in the executed DAG becomes the presentation pass automatically (there is no explicit `present(...)` API).
- A pass viewport goes to wgpu as given, within wgpu's limits, and the scissor rect is the viewport clipped to the pass's color attachment. Output past the attachment is cropped, never squeezed. A viewport that clips to nothing keeps the pass's clear and skips its draws, because Metal can't take an empty scissor.

MSAA & resolves
- Use transient MSAA textures from the texture pool and resolve into the target view. Take them with `Lease::take`, which returns the texture to the pool when the lease drops, error paths included.
- `RenderContext::render` calls `TexturePool::start_render` once when it acquires a frame (compute-only renders don't count), which frees entries no render used for `IDLE_RENDERS` renders, so a target that changed size doesn't keep its old textures.
- Sample count is negotiated per adapter/format via `pick_sample_count` and cached in `RenderContext`.

Bind groups & alignment
- Sort bind group entries by binding index; create empty groups for expected-but-unused groups so indices stay stable.
- Uniforms: align to `device.limits().min_uniform_buffer_offset_alignment`.
- Uniform and storage pools rewind once per `render`, never per pass. `queue.write_buffer` applies at submit, so passes that share a submit need distinct offsets.
- Storage buffers: bind the full buffer (`size: None`) to avoid backend padding surprises.
- Push constants: prefer native push constants when the adapter supports them; fall back to a per-root uniform buffer otherwise (single source of truth in `PushMode`).

Lights (`lights.rs`, `lights/grid.rs`, `light_binning.wgsl`)
- `Renderer::context` picks a `LightPath` once per context from the adapter and device, never from `cfg(wasm)`. `Clustered` needs a backend other than GL, compute shaders, fragment storage, two storage buffers per stage, 64-thread workgroups, 54 workgroups per dimension, 4 KiB of workgroup memory and a 1 MiB storage binding. Every other device, WebGL2 and native GL included, takes `Uniform` with a block of `(min(max_uniform_buffer_binding_size, 64 KiB) - 144) / 64` lights. The path lives on the context, so `RenderPipelineKey` has no light field, and a test that forces a path uses a fresh `Renderer`.
- The context lowers the process-wide light cap (`shader::lower_light_cap`), which `Pass::add`, `Pass::add_shader` and `Model::attach` check before they change anything. The cap always comes from the device.
- `plan_pass` runs `check_light_cap` before the frame is acquired, so a lit shader past the context's cap fails with `RendererError::PassError(LightCapReached)` with no frame taken and no light buffer touched. That catches lights added before the device opened.
- `prepare_lights` runs in `process_render_pass` before `begin_render_pass`, and nowhere else. It records the binning compute pass on the frame encoder. It touches buffers only, so the Apple compute split doesn't apply.
- Lit shaders on a pass share a `LightSet` when their light lists, ambient terms and root shapes match, keyed by `(pass id, set key)`, with the shader in the key when the pass has no `Camera`. Each shader caches its `LightSummary` (the hash of its live light ids, ambient and placeholder, and the live count) per light epoch, so keying and the cap check walk no lights on a frame where no light changed. A set taken from the idle pool forgets what it packed, uploaded and binned.
- Sets stay out of `storage_registry` and the per-frame pools. `submit` calls `start_light_render` right after `TexturePool::start_render` on every render that draws: it frees a set unused for `IDLE_RENDERS` renders, and after a failed frame (`lights_failed`) it makes every set pack, upload and bin again, since that frame's binning never ran.
- Each set is prepared at most once per render. It repacks when the light epoch moved, writes the header when it changed and the lights from the first changed one to the last, and rebins only when a bounding sphere, the binning matrix or a buffer changed. A set whose shaders declare no `light_grid` never bins and holds no grid or bins buffer. A still scene dispatches once, and a pass with no binned light never dispatches.
- A storage root packs the lights without a range first, each part in attach order. The older `LightArray` packs them in attach order.
- The bind loop binds each lit shader's light buffers whole, with `size: None`, before the reflected uniforms. Light root layout entries are visible to `FRAGMENT`, plus `VERTEX` when the vertex entry reads a root, and the push-constant fallback group sits past the highest reflected or light group.
- The binning pipeline builds once per context inside `validate`; a native failure isn't cached. CPU-side math in `lights/grid.rs` mirrors the WGSL, and `constants_match` keeps the grid constants and struct offsets of the three WGSL files in step with Rust.
- Mesh buffers belong to the device that drew the mesh first, so a GPU test that compares renderers builds a new pass for each one.

Mobile uniffi path
- Methods on `Renderer` that need to be uniffi-exported live in `platform/mobile/`; keep them concrete-typed (uniffi cannot marshal `impl Trait`).
- Platform-specific constructors (e.g. `create_target_ios`) go in `platform/mobile/{ios,android}.rs` and are wrapped by idiomatic Swift/Kotlin extensions in `platforms/{swift,kotlin}/`.

Code structure
- Avoid large nested closures; extract helpers or keep logic linear.
- Keep the public API thin and delegate internally.
- Maintain zero warnings; prefix intentionally unused variables with underscore.
