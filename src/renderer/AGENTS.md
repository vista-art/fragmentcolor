# AGENTS.md — Renderer rules (short)

Core invariants
- Draw the meshes attached to a Shader with one RenderPipeline per vertex layout. Meshes with equal layouts share a pipeline, and the draw loop and the blend phase switch pipelines when a mesh's layout differs from the one before. A shader's pipelines have the same bind group layouts, which wgpu dedupes, so one set of bind groups serves them all: `ShaderState::bind` sets them once for the shader, and `switch` sets only the pipeline and the native immediates, which a pipeline of another layout clears.
- Pipeline cache keys are descriptive structs, not tuples:
  - `RenderPipelineKey { shader_hash, color_format, depth, sample_count, alpha_mode, double_sided, vertex_layouts }`, where `depth` is a `DepthUse` (`src/renderer/depth.rs`)
  - `ComputePipelineKey { shader_hash, bind_group_entries }` (layout entry contents, never resource addresses)
  Do not rely on tuple ordering; extend these structs if new state starts to affect pipeline configuration.
- If a shader has no `@location` vertex inputs, draw a single fullscreen triangle (three built-in verts). A shader that reads `@location` inputs and has no mesh returns `ShaderError::InvalidKey` naming the first one, before any pipeline is built. The inputs come from `reflect_vertex_inputs`, which flattens the `@location` members of struct arguments, so the layouts and this check treat a member like an argument.
- Vertex layouts come from each mesh (`vertex_buffer_layouts`, kept by the mesh until it changes) and are part of the pipeline key, since one shader can feed meshes with different layouts. The plan reads them before any pipeline builds, and `check_strides` refuses a stride past `max_vertex_buffer_array_stride` with `LimitError`, the instance stride only when the shader reads it. An input location past `max_vertex_attributes` is the shader's own refusal, in its verdict (`judge_shader`). On WebGL2 the device opens with a 255-byte stride limit (`cap_limits`), which WebGL's `vertexAttribPointer` takes and wgpu doesn't report.
- A mesh with an empty index list draws nothing.
- A shader that draws any of the pass's Models, hidden ones included, skips a mesh that gets instances only from Models (`MeshObject::awaits_models`) when no visible Model in the pass draws it through that shader. The pass's Model buffers are keyed by (shader, mesh), so another shader's visible Model on the same mesh doesn't count. That covers a hidden Model and a Model added to another pass through a shared Material. Drawing it would read whatever buffer an earlier mesh left in slot 1. Every other draw goes on: the same mesh in a shader of its own or in the quick view, and a mesh with instances of its own, even instances without properties.
- When no Model drives the draw and the pipeline reads instance attributes, a mesh draws no more instances than it holds, and a larger count returns `MeshError::InvalidInstance`. That covers a `set_instance_count` past the instances, and a shader that reads the Model columns for a Model's mesh while drawing no Model in the pass, whose message names the columns it reads (`name_columns`). A pipeline that reads no instance attribute draws any count, from instances without properties too.

Error scopes & the pipeline cache
- `RenderContext::validate(label, op)` is the one place GPU work runs in error scopes. It pushes one scope per filter in `SCOPES` (out of memory, internal, validation) and pops them in reverse order on every path, `op`'s own errors included. Of what they catch, `Caught::split` takes the cause in that order, since running out of memory or an internal failure leaves an object whose next use fails validation. The errors it leaves go to the log. `SCOPES` pairs each filter with the `ErrorKind` its errors report (out of memory is `Memory`), and `Caught::split` tags each error with the kind of the scope that caught it. On native the cause returns from that call as `RendererError::DeviceError { kind, label, .. }`.
- On native, `scope::Origin` records per thread where `op`'s error came from. When it came from the GPU (a nested scope caught it, or the surface failed validation and sent its details to the device), the cause the outer scopes caught came first, and it returns under the outer label. A CPU error from `op` wins, whatever its variant, and the GPU error goes to the log as a warning. On wasm `op`'s own result always returns, and `ErrorSlot::watch` logs the scope's errors at error level when they land, storing none of them when `op` failed.
- Pipeline builds and the frame use `validate`. A step inside a frame (a bind group, a texture view) uses `validate_step`, which scopes it on native so its error keeps the step's label, and runs it bare on wasm, where the frame's scopes cover it.
- Each render and compute pipeline comes from `fetch_pipeline`, which builds a miss inside `validate_with` and inserts only what built, so on native a pipeline that failed is never cached and the next frame reports the same error.
- Each frame records its passes and submits them inside one `validate("frame", ..)`. `submit` calls `plan_pass` for every render pass before `acquire_frame`. It checks the light cap (`check_light_cap`), builds the pass's Model buffers (`build_pass_draws`, refusing a buffer past `max_buffer_size`), and decides each mesh's layouts (`vertex_buffer_layouts`), buffers and instances (`pick_instances`). The CPU checks that need no frame run there (a lit shader past the light cap, a shader that reads vertex inputs with no mesh, a mesh asked for more instances than it holds, a mesh past the device's vertex or buffer limits, a missing pass target), so those errors acquire no frame, and the draw loop draws from the plan without deciding again. A compute pass runs `check_compute` there instead, and `check_owner` refuses a target another context created before `acquire_frame`. A frame that was acquired is presented on every path, failed ones included: Vulkan takes an acquired image back only through a present, and dropping it leaks a swapchain image. wgpu clears an image that no valid submit drew into. On Apple the encoder is submitted before each compute pass that follows another, so a pass after that split that fails leaves what the earlier submit drew.
- On wasm a scope resolves after `render` returns. `validate` hands the popped scopes to `ErrorSlot::watch` (`late.rs`). Each error that lands goes to `log::error!`, a `console.error` that the web healthcheck fails on outside its `late_errors` module, and the first one waits in `RenderContext::late`. `render` takes it before any GPU work. `load`, `read_storage` and `read_texture` wait for earlier frames first, and so does `read_pixels`, which both `get_image` call. Each takes a `Start` (`Start::now`, the slot's `mark`) when the call starts, and `Start::settle` waits until every scope opened before it has landed. `read_texture` settles and then calls `copy_pixels`, so it settles once. The slot keeps the ticket of the scope that stored its error, and `settle_from` takes the error only when that ticket comes before the start, so an error from a frame rendered while the call waits stays for the next call. A JS export's future first runs on a later microtask, so `readTexture`, `readStorage`, `load` and both `getImage` are plain functions that take their `Start` before they return the promise. Otherwise a frame rendered in the same task, right after the call, would count as earlier. The `_from` methods take that `Start`, and a Rust `async fn` takes its own on its first poll. `render` takes whatever waits, since every stored error landed before it was called. Only the first error that lands while the slot is empty is returned, once. One that lands while another waits only logs, and a readback whose error another call took first returns its bytes.
- On wasm a pipeline's error lands after the insert, so the failed pipeline stays cached until then, and frames that use it meanwhile report a frame error. When the error lands, `validate_with` runs an eviction, so the next frame that draws with it builds it again and reports the same error. In a loop that renders each frame, the `render` right after the error landed throws it before any work, and the one after that builds the pipeline again. A check that has to fail in the same call on the web runs on the CPU before any wgpu call.

Device checks (`shader_checks.rs`, `layout.rs`)
- `layout::plan_layout` lays out a shader on the CPU: the reflected slots, the light roots (render only), and where the immediate roots go (`PushMode`). Native immediates take one root that fits `max_immediate_size` on a device with `IMMEDIATES`, never on wasm; otherwise each root is a uniform in the lowest group no slot uses. The checks and both pipeline builds read this one layout, so they can't drift, and `texture_binding` is the one mapping from a texture slot to its `wgpu::BindingType`.
- `plan_pass` (render) and `plan_compute` (compute) run `check_shader` and `check_textures` for each shader before `acquire_frame`, ahead of the pass checks below. `check_shader` refuses groups, bindings, per-stage counts and buffer sizes past the limits, a render shader's vertex input at a location past `max_vertex_attributes`, storage the device can't bind, a render shader without its entry points, a compute shader on a device without compute or with a workgroup past the limits (sizes, invocations and workgroup memory, overrides at their defaults), an explicit `@size`/`@align` buffer layout on a GL backend, a render shader that calls `arrayLength` on `lights` or `light_grid` on the uniform light path (`check_measured`), a struct whose layout `write_layouts` can't keep on the browser's WebGPU, and a module the device's naga validator refuses. The GL layout and `arrayLength` checks read the shader's own module and light roots, before `build_module` pads and lowers them, so `lower_roots` meets a measured root only as a backstop. Its `Verdict`, passed or refused, goes in `RenderContext::checked` by source hash, so each source is checked once per context and a refused one returns the same error each frame. `check_textures` runs every frame against `TextureFacts`: a texture uniform needs a texture its slot takes by wgpu's binding rules. Only an unset (id 0) PBR map slot of a render shader falls back to its default, and only when its slot takes the default's facts; a compute pass binds no default.
- The context reads the device's features, limits and downlevel flags once (`RenderContext::features`, `limits`, `downlevel`), since each read crosses into JavaScript on the browser's WebGPU. Checks use these fields, never `device.features()` in a loop.
- Errors: `LimitError { item, limit, value, max }` for anything past a limit, `FeatureError { item, feature }` for a feature or downlevel flag the device lacks, whose `item` names the thing refused (a slot, a struct, `the shader`) and holds no advice, `BindingError { uniform, expected, found }` for a slot whose texture doesn't fit or was never set, `EntryError { stage }` for a missing entry point, and `TextureNotFoundError` for a removed or foreign texture. Python raises an exception class of each name, JavaScript an `Error` of that `name` with the fields as properties, and Swift and Kotlin the `Limit`, `Feature`, `Binding` and `Entry` cases. `DeviceError` stays for what an error scope catches.
- Pipeline builds keep every CPU check (`find_entry`) before their first wgpu call. They look each entry point up in the names `pick_source` returns for the module wgpu receives: after `build_module`, and for a render pipeline after `set_encoding`, which sets `ENCODE_SRGB` from the target format. Compute pipelines fill group gaps with empty layouts and groups, as render pipelines do, and set native immediates after `set_pipeline`.
- On the browser's WebGPU (`writes_wgsl`), `layout::pick_source` hands wgpu WGSL from `write_layouts` for a module whose buffer structs set `@size`/`@align`, since the WGSL wgpu writes from a naga module drops them. `check_shader` runs `write_layouts` on the module it validates and keeps a failure as a `FeatureError` verdict, so `pick_source` meets that error only as a backstop. Every other module and backend gets the naga module. wgpu hands the browser naga's WGSL writer output for a naga module too, and that writer renames an entry point that ends in a digit or an underscore or whose name a type took, so on the browser's WebGPU `pick_source` returns the names `name_entries` predicts, from the module it hands wgpu, and the pipeline asks for those.

Pass checks (`checks.rs`, `access.rs`)
- Each rule here is one wgpu enforces, checked on the CPU first so every platform gets a typed error from the call that broke it. On wasm a wgpu error lands only after `render` returns.
- `find_targets` looks up the color and depth targets a pass set. One the context doesn't hold, because `unregister_texture` removed it or another `Renderer` created it, returns `TextureNotFoundError`. The draw loop uses the objects it found.
- The plan applies each shader's queued sets (`flush_pending`) before any check reads its bindings.
- `check_attachment` checks a pass against its color attachment: the depth target's size (`DepthSizeMismatch`) and sample count (`DepthSampleCountMismatch`), each shader's `@location(0)` output against the format (`check_output`, wgpu's rule: the same scalar kind, at least as wide, at least as many channels), `AlphaMode::Blend` against the rules every device shares (`check_blend`: `InvalidColorTarget` for a format that never blends, and for an output that isn't a `vec4`, the WebGPU rule for blend factors that read the source alpha), and texture uses. Last, once every shader passed those, a blended pass checks `BLENDABLE` from `texture::format_features`, which reads the cached `features` and `downlevel` (`check_blendable`: `FeatureError` for a format this device can't blend and another can), so `check_attachment` gives a pass the same error on every device until only the device's blending is left. A pipeline writes no color channel (`pick_color_writes`) when its fragment entry point writes nothing at `@location(0)`, as WebGPU requires. The device opens with `FLOAT32_BLENDABLE` wherever the adapter offers it. `plan_pass` runs it for a pass with its own target, and `process_render_pass` runs it against the frame, before `prepare_lights` and `begin_render_pass`.
- `Accesses` records each texture a usage scope touches, keyed by its `wgpu::Texture`: a whole render pass, attachments included, or one compute dispatch, which is one shader. Reads share a texture, and each kind of write (color, depth, each storage access) needs it alone, as in wgpu's usage tracker. A conflict returns `PassError::TextureConflict`.
- `check_compute` refuses a dispatch past `max_compute_workgroups_per_dimension` with `PassError::DispatchLimit`, and a dispatch that reads and writes one texture.
- `check_owner` compares `FrameSource::owner` with the rendering context, at the top of `submit` before any pass is planned, since planning uploads mesh buffers to the context's device. `Renderer::render` runs `check_target` before `load`, after the wasm late error, so a refused render uploads nothing, opens no device, and binds nothing into a shared shader. It lists the passes with `Renderable::peek_passes`, which runs no setup such as a Scene's default camera and light, and it refuses a pass target or bound texture whose `Registration` another context holds (`belongs_to`) with `TextureNotFoundError`, the error `find_targets` and `check_textures` give in the plan. A `Renderer` without a context refuses every render there: `ForeignTarget` for a drawing render into a target with an owner, `NoContext` otherwise. `Renderer::context` creates the context once under `context_lock`, so calls that race share it. Each `Renderer` has its own wgpu instance, so a frame from another one panics inside wgpu-core. A render of compute passes alone draws into no frame, so it skips only the frame owner comparison (`check_owner` in `submit` and `ForeignTarget` in `check_target`). It still gets `NoContext` without a context and `TextureNotFoundError` for a foreign bound texture. On native `check_target` skips a binding that the latest queued upload of its key replaces (`find_replaced`), since `render` runs `load` first.

Depth
- `RenderContext::resolve_depth` picks each render pass's depth attachment. A depth target the pass set wins, and `check_attachment` has matched its size and sample count to the color attachment's. Otherwise a pass with Models takes a pooled `Depth32Float` sized and sampled like its color attachment, cleared to 1.0 and discarded at the end. Any other pass draws without depth, in order.
- In a pass that draws Models, a shader that draws none of them (a fullscreen backdrop, an overlay mesh) uses `DepthUse::Ignore`, with the pooled depth or a depth target the pass set: it passes every fragment and writes no depth, so it draws in order and hides no model. In a pass without Models, an explicit depth target makes every shader test depth. Every pipeline in a pass declares the attachment's format, so ignoring depth is a pipeline state, never a missing attachment.
- A render pass takes its size from `TargetFrame::size`, never `Target::size`. A resize can land between acquiring the frame and drawing, and every attachment must match the frame.
- Blend draws test depth and never write it.

Render targets & present
- If no per-pass offscreen target is set, render to the provided final frame by default.
- Per-pass targets render intermediate results; the last render pass in the executed DAG becomes the presentation pass automatically (there is no explicit `present(...)` API).
- A pass viewport goes to wgpu as given, and the scissor rect is the viewport clipped to the pass's color attachment. `check_viewport` refuses a side past `max_texture_dimension_2d` with `PassError::ViewportLimit` in `plan_pass`, so no size is ever shrunk to fit. Output past the attachment is cropped, never squeezed. A viewport that clips to nothing keeps the pass's clear and skips its draws, because Metal can't take an empty scissor.

MSAA & resolves
- Use transient MSAA textures from the texture pool and resolve into the target view. Take them with `Lease::take`, which returns the texture to the pool when the lease drops, error paths included.
- `RenderContext::render` calls `TexturePool::start_render` once when it acquires a frame (compute-only renders don't count), which frees entries no render used for `IDLE_RENDERS` renders, so a target that changed size doesn't keep its old textures.
- Sample count is negotiated per adapter/format via `pick_sample_count` and cached in `RenderContext`.

Bind groups & alignment
- Sort bind group entries by binding index; create empty groups for expected-but-unused groups so indices stay stable.
- Uniforms: align to `device.limits().min_uniform_buffer_offset_alignment`.
- Uniform and storage pools rewind once per `render`, never per pass. `queue.write_buffer` applies at submit, so passes that share a submit need distinct offsets.
- Storage buffers: bind the full buffer (`size: None`) to avoid backend padding surprises.
- Push constants: prefer native push constants when the adapter supports them; fall back to a per-root uniform buffer otherwise (single source of truth in `PushMode`, decided by `layout::plan_push` for render and compute alike).

Lights (`lights.rs`, `lights/grid.rs`, `light_binning.wgsl`)
- `Renderer::context` picks a `LightPath` once per context from the adapter and device, never from `cfg(wasm)`. `Clustered` needs a backend other than GL, compute shaders, fragment storage, two storage buffers per stage, 64-thread workgroups, 54 workgroups per dimension, 4 KiB of workgroup memory and a 1 MiB storage binding. Every other device, WebGL2 and native GL included, takes `Uniform` with a block of `(min(max_uniform_buffer_binding_size, 64 KiB) - 144) / 64` lights. The path lives on the context, so `RenderPipelineKey` has no light field, and a test that forces a path uses a fresh `Renderer`.
- The context lowers the process-wide light cap (`shader::lower_light_cap`), which `Pass::add`, `Pass::add_shader` and `Model::attach` check before they change anything. The cap always comes from the device.
- `plan_pass` runs `check_light_cap` before the frame is acquired, so a lit shader past the context's cap fails with `RendererError::PassError(LightCapReached)` with no frame taken and no light buffer touched. That catches lights added before the device opened.
- `prepare_lights` runs in `process_render_pass` before `begin_render_pass`, and nowhere else. It records the binning compute pass on the frame encoder. It touches buffers only, so the Apple compute split doesn't apply.
- Lit shaders on a pass share a `LightSet` when their light lists, ambient terms and root shapes match, keyed by `(pass id, set key)`, with the shader in the key when the pass has no `Camera`. Each shader caches its `LightSummary` (the hash of its live light ids, ambient and placeholder, and the live count) per light epoch, so keying and the cap check walk no lights on a frame where no light changed. A set taken from the idle pool forgets what it packed, uploaded and binned.
- Sets stay out of `storage_registry` and the per-frame pools. `submit` calls `start_light_render` right after `TexturePool::start_render` on every render that draws: it frees a set unused for `IDLE_RENDERS` renders, and after a failed frame (`lights_failed`) it makes every set pack, upload and bin again, since that frame's binning never ran.
- Each set is prepared at most once per render. It repacks when the light epoch moved, writes the header when it changed and the lights from the first changed one to the last, and rebins only when a bounding sphere, the binning matrix or a buffer changed. A set whose shaders declare no `light_grid` never bins and holds no grid or bins buffer. A still scene dispatches once, and a pass with no binned light never dispatches.
- A storage root packs the lights without a range first, each part in attach order. The older `LightArray` packs them in attach order.
- The bind loop binds each lit shader's light buffers whole, with `size: None`, before the reflected uniforms. Light root layout entries are visible to `FRAGMENT`, plus `VERTEX` when the vertex entry reads a root, and the immediate fallback group takes the lowest group no reflected or light slot uses.
- The binning pipeline builds once per context inside `validate`; a native failure isn't cached. CPU-side math in `lights/grid.rs` mirrors the WGSL, and `constants_match` keeps the grid constants and struct offsets of the three WGSL files in step with Rust.
- A mesh keeps buffers for the context that drew it last, keyed by `RenderContext::id`, and a context that finds another's buffers uploads its own. wgpu compares the devices of two instances by an index both reuse, so the id tells contexts apart.

Mobile uniffi path
- Methods on `Renderer` that need to be uniffi-exported live in `platform/mobile/`; keep them concrete-typed (uniffi cannot marshal `impl Trait`).
- Platform-specific constructors (e.g. `create_target_ios`) go in `platform/mobile/{ios,android}.rs` and are wrapped by idiomatic Swift/Kotlin extensions in `platforms/{swift,kotlin}/`.

Code structure
- Avoid large nested closures; extract helpers or keep logic linear.
- Keep the public API thin and delegate internally.
- Maintain zero warnings; prefix intentionally unused variables with underscore.
