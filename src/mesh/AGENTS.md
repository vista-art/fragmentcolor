# AGENTS.md — Mesh rules (short)

Schema & packing
- Derive the vertex / instance field list from the first vertex / instance added. Field names, order and sizes stay stable for the mesh lifetime, except that `clear_instances` drops an instance layout built from instances (a `Model`'s declared columns stay) and the next instance sets it again.
- A typed value (a Rust `f32` or `u32`) fixes its field's format. An untyped field (plain numbers, the form every binding sends) takes the format of the first shader that reads it, for the mesh's lifetime, and packs as floats until one does. A recorded type wins over a later typed value, which then fails the attach and the pack. Typing never moves an offset or the stride, since every component is 4 bytes.
- The pack derives and stores a missing schema under that schema's lock, held while it packs, and `types` is a leaf lock, so an attach running at the same time can't leave a schema derived from old types.
- `Vertex` and `Instance` values never change at attach: the same vertex can sit in two meshes whose shaders type it differently. The recorded types live on the mesh (`MeshObject.types`).
- Pack at render (`ensure_packed`), converting each value to its field's format. Values added after the attach are checked there and fail with `MeshError`. `declare` records the attributes each attached shader reads, with their formats, under the shader's `id` (`required`), and a vertex or instance that lacks one fails the pack. A read no attached shader had before marks its stream changed, so the next pack checks it. The quick view's shader records no reads: it checks the mesh itself whenever the mesh's `generation` moved, on every render that draws it, before the pack and after it (`ShaderObject::check_preview`). An instance layout that lacks one, after `clear_instances`, fails too (`check_layout`), and so do no instances at all for a shader that reads them. `detach` drops a shader's reads when it lets the mesh go, while `types` stay for the mesh's lifetime. Only a field no attached shader reads packs as zeros.
- `position` names the built-in position (`vertex::POSITION`), so a vertex property of that name fails the pack with `InvalidVertex`, as it fails the attach.
- A mesh draws a triangle list, its only topology. Indices from `set_indices` are checked on every repack (`check_indices`): a multiple of 3 (`IndexCount`), each below the vertex count (`IndexRange`). Without them the vertices must come in threes (`check_vertices`, `VertexCount`). The check runs under the same hold of the vertices as the pack, on the list the pack stores in `Packed::indices`, so the list checked is the list uploaded. The vertices stay unpacked until they fit.
- An instance row is one entry of the instance list, so instances without properties count, though they pack no bytes. The pack records the rows next to the bytes (`Packed::rows`), and the upload draws those.
- Each stream counts its changes (`vertex_changes`, `instance_changes`), and `Packed` keeps the counts its bytes come from. A mutator changes the data and bumps its count, then `generation`, before it lets the data go, and the pack reads the counts before the data. So a change that lands during a pack leaves its stream to pack again, and a pack sees no change that `generation` doesn't count yet, which the quick view's check after the pack relies on. Only the pack writes `Packed`. Recording a new type resets the schema that lists it and marks its stream changed; an attach that records nothing keeps the packed bytes and GPU buffers.

GPU buffers
- `upload(context)` must create / update and cache GPU buffers; avoid re-allocating unless a repacked stream demands it.
- The buffers belong to one `RenderContext` at a time (`GpuStreams::owner`, its `id`). Another context gets buffers of its own, uploaded from the packed bytes, so a mesh draws with any `Renderer`.
- The cached upload holds its owner, its buffers, its counts, the schemas its bytes follow (`Packed::schemas`) and the mesh's `generation` when it began in one value (`Cached`, `Upload`), so an upload never reaches another context. An upload holds the `gpu` lock from the pack to the cache it fills. `invalidate_cache` only moves `generation`, takes no lock, and makes every older result and layout stale.
- The mesh keeps each attached shader's vertex layouts (`fetch_layouts`), in the same `required` entry as its reads, until the mesh changes or the shader lets it go, so a still scene builds none and a dropped shader leaves none. They come from the schemas of the upload the frame draws and stay under its generation, never from the live schemas, which an attach on another thread can reset between the upload and the layouts. The renderer checks them against each device's limits on every frame.
- Every upload checks each buffer against `max_buffer_size` (`check_limit`, `RendererError::LimitError`, which is why `upload` returns a `RendererError`) before deciding what to write. An upload that fails, on a pack, a count or a limit, leaves each stream it packed unpacked (`Packed::forget`), so the next one packs and writes it again instead of drawing old buffers.
- A `Model` attach assumes the Model columns for a mesh with no instances and no instance layout (`bind_mesh_with`), and `declare` sets them only when it records the reads, so a refused Model sets nothing and leaves nothing to undo. It sets them before it records the reads, so a pack in between finds the layout those reads need.
- Instance buffers are optional; `instance_count` can be overridden to drive non-instanced draws.

Validation contract
- Mesh compatibility is validated by `Shader::add_mesh` at attach time. It checks every vertex and instance value and records types only when it succeeds; `Shader::validate_mesh` records nothing. The attach holds the shader's mesh list from `declare` to the push, so a `remove_mesh` or `clear_meshes` that comes meanwhile can't drop the reads it records. Lock order: the shader's mesh list, then the mesh's locks.
- Reject invalid attachments with `ShaderError` (`AttributeMismatch`, `AttributeConflict`, `InvalidKey`). Never silently accept a mismatched mesh.

Builders & primitives
- Provide idiomatic builders for common shapes (currently `Quad`). Keep them under `mesh/primitives/` and expose via the mesh module re-exports.
