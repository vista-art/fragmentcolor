# AGENTS.md — Texture & Target rules (short)

Lifecycle & creation
- `TextureTarget` is always created by the `Renderer` (direct construction is crate-private) so usage flags and format negotiation stay correct.
- Prefer the `Renderer::create_texture*` helpers — they wire up the proper `wgpu::TextureUsages`, register the texture with the context, and hand back a typed `Texture` / `TextureId` handle.
- An explicit texture's registry entry lives as long as its `Registration` (`src/texture/registration.rs`), which also holds the texture's current `TextureObject`. `Texture` and `TextureTarget` read the object through it, so a resize that swaps it (`Registration::replace`, which also repoints the registry) reaches every handle and clone. Read one snapshot (`object()`) per operation, and never hold the cell's lock across an `.await`. Every `Texture` handle shares one, the owning `TextureTarget` holds it, and so do a pass target (`ColorTarget`, `DepthTarget`) and a shader uniform (`ShaderObject::bound_textures`). The last one to drop removes the entry. Anything new that keeps a texture to draw later holds the registration too, never a bare `TextureId`: an id alone doesn't keep the texture. A Material map is the one exception, below.
- Texture ids are unique across renderers, because a shader binding finds the registration to hold from its id. A Material map's id is the one exception: it names one copy in each Renderer that loaded the map. Registrations and maps take their ids from one counter (`TextureId::create`), so a map's id never equals an explicit texture's.
- A map's copy is the one registry entry with no `Registration`, since one map id names a copy in each Renderer and a `Registration` belongs to one context. The context's registry owns it. The map's `Drop` (`TextureMap` in `src/core/shader/uniforms/texture_maps.rs`) or the context's own drop frees it, and a copy that `unregister_texture` removed uploads again at the next `load`. Only the map's own slot binds its id: any other slot refuses it with `ShaderError::ForeignMap`, since nothing else keeps the copies.
- Every upload reads a `TextureSource` (`loading/source.rs`): the data sits in one `Arc<SourceData>`, which can't hold `Empty` or `CloneOf`, so a source's clones and its uploads in each Renderer share one buffer. The glTF loader keeps each image encoded (`read_images` in `src/scene/loader.rs`): a GLB buffer view's or a data URI's bytes, copied out once so no vertex data stays with them, or an external file's path. It gives every slot that reads the image a `TextureSource` of that one source, with the slot's own sampler, so a scene keeps about its file's size in RAM and each Renderer decodes at its own load. `Scene::load` reads each header (format and size, `check_header`) and refuses what it can't read. A corrupt body fails only at the first upload, and the source's `label` (`TextureSource::named`, `TextureError::name`) puts the image's name in that error. Code that compares two sources compares that pointer (`Arc::ptr_eq`), never the contents.

Creation checks
- A texture a caller describes passes the checks in `src/texture/` before any `device.create_texture` or `queue.write_texture`: `check_usage` takes only the five `TextureUsage` flags, `check_format` takes the features, usages and dimension the device allows for the format (`format_features` follows wgpu: the adapter's own table on GLES and WebGL2, the WebGPU baseline elsewhere), `check_extent` takes the device limits, `check_upload` refuses a buffer copy into a depth format, and `check_decode` takes the formats a decoded image fills. A missing wgpu feature returns `TextureError::UnsupportedFormatForUsage`, and every other failed check returns `TextureError::InvalidInput`, the error `resize` returns.
- Copies move one texel at a time, and `texel_size` reads its size from wgpu's format data, so a block-compressed texture refuses `write` and readback. Never guess a size per pixel.
- No input drops what the caller gave. A `Texture` keeps the options it was created with, so `create_texture` and the Material setters refuse options beside one (`TextureInput::check_options`, an `InvalidInput` that names the call). A source that stores its own format, a `Mipmap` or a KTX2 container from bytes, a path or a URL, uploads in that format or its sRGB twin, which reads the same bytes, and any other format is an `InvalidInput` that names the call (`Pick::apply`; `from_source` takes the call, `create_texture` or `load`). A Material slot's format is a hint (`TextureSource::take_hint`, `hinted`): an image uploads in it, and a stored format takes it only where its bytes read in it, so a float chain or container keeps its own and the hint never refuses.
- Raw bytes are exactly the size of their region. A `size` comes with raw bytes only, since a path, a URL, a KTX2 file and a `Mipmap` carry their own, and a decoded image's header size is checked before its pixels decode.
- A decoded image, a JS `ImageData` and a canvas hold RGBA, so each stores blue first in a `Bgra8` format through `swap_bgra`, on every path that takes it. In JS that path is `js_to_texture_bytes` or `read_texture_input`, never a bare byte read. Raw bytes, a NumPy array among them, keep their order.

Binding & sampling
- Texture views are created per bind. Each texture keeps one sampler built from its `SamplerOptions` and rebuilds it in `set_sampler_options`.
- Bind texture + sampler pairs in consistent groups; fill missing groups with empty bind groups so group indices stay stable.
- A `sampler` binding takes its options from a texture in the same group: the lowest binding between the previous sampler and itself, else the nearest one. `SamplerSources` in `src/core/renderer/frame/samplers.rs` owns the rule; the binding's comparison flag wins over the texture's `compare`.
- `UniformData::Texture` carries `TextureMeta` (dim, arrayed, class) so `shader.set("tex", &texture)` only updates the id while preserving the reflected metadata.
- The renderer checks each bound texture against its slot before the frame (`core/renderer/checks/shader.rs`, `check_texture`): usage, format, the default view's dimension, sample count, and for a storage slot one mip level. A texture view always uses the default descriptor, so a `texture_cube` slot takes no FragmentColor texture yet.

Updates & readback
- `Texture::write(&bytes)` uploads a whole-texture frame; `Texture::write_region(&bytes, region)` handles sub-rectangles, layered/3D textures, and explicit source layout. The `region` arg accepts `[w,h]`, `[x,y,w,h]`, `[x,y,z,w,h,d]`, a `ScreenRegion` (its pixel rectangle at `z = 0`, one layer deep), or a `TextureRegion` constructed with `.with_stride(...)` / `.with_rows(...)`. JS objects and Python dicts go through `region::read_region`, the one reader both bindings share. A side of 0 in an array, tuple, object, dict or `TextureRegion` is an `InvalidInput` error, a `ScreenRegion` whose max lies before its min, or with a side of 0, is `TextureError::Region` with `ScreenRegionError::Reversed` or `Empty`, and only a missing region (`write`, a JS `undefined`, a Python `None`) means the whole texture.
- A whole write into a texture with a mip chain rebuilds the chain on the CPU, and a partial write into one is refused, since it would leave the smaller levels stale.
- Every readback copies mip 0 of each layer into tightly packed bytes in the texture's format through `copy_pixels` (`read.rs`). `Texture::get_image()` and `Renderer::read_texture` return them as they are, and `TextureTarget::get_image()` swaps a `Bgra8` target's bytes with `swap_bgra` to return RGBA8 for CI and snapshot tests.
- A texture without `COPY_SRC` returns `TextureError::Error`. `TextureError::Readback` comes back when the backend copies no depth texture, the copy needs a buffer past `max_buffer_size`, or the buffer fails to map in time. Every native readback, the storage one included, waits through `wait_for_map` (`core/renderer/pools/readback.rs`), which polls the device in steps of 100 ms until the map callback fires and gives up after `MAP_LIMIT`, since nothing else may poll the device and a callback alone never wakes. A window target's `get_image()` always returns `TextureError::Readback` (`window::unreadable`), because a frame on screen can't be read back.
- On wasm a readback first returns the first GPU error an earlier frame left, with the kind and label `render` would report: `TextureError::DeviceError` from `get_image()` and `RendererError::DeviceError` from `read_texture`. `read_pixels_from`, behind the `get_image()` of a texture or texture target, settles from the call's `Start` and then calls `copy_pixels`. `Renderer::read_texture` settles before it looks up the id and then calls `copy_pixels`, so it settles once. A readback takes only an error that a scope opened before its `Start` stored, and the JS `getImage` exports take that `Start` before they return their promise. A new readback goes through one of them, and a window target's `get_image()` returns its error without settling.

MSAA & resolve
- For MSAA render passes, render to transient MSAA textures from the pool and resolve into the target view; release to the pool after use.
- Sample count must match between color and depth attachments within a pass, and `RendererError::DepthSampleCountMismatch` reports a mismatch. So must the width and height, with `RendererError::DepthSizeMismatch`.
- A pass target holds one mip level of one layer, so `set_target` and `set_depth_target` refuse a texture with a mip chain or layers.
- A pass never binds a texture it draws into, and a usage scope never reads a texture it writes (`core/renderer/checks/texture_conflicts.rs`).
