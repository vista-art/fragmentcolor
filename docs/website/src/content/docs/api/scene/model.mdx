## Description

A `Model` pairs a [Mesh](/api/geometry/mesh) with a
[Material](/api/scene/material) and adds a per-Model
4×4 transform. It's the unit you actually add to a `Pass` when rendering 3D
content; the Material handles shading, the Mesh handles geometry, the Model
handles "where in the world".

Each `Model::new` takes ownership of the Material it's given. Cloning the
Material before passing it in is cheap: `Material::clone` shares the handle
and copies nothing. The per-Model transform is *not* a Material uniform. The
renderer reads it at draw time and feeds it to the vertex stage as four
`vec4<f32>` instance attributes, `model_0` to `model_3`, the columns of a
`mat4x4<f32>`. The PBR shader reads them at locations 3 to 6.

Models that share a Material and a Mesh draw together. On every render, the
renderer packs the transforms of the visible `Opaque` and `Mask` Models with
the same Shader and Mesh into one instance buffer and draws them in one
instanced call. `Blend` Models draw one at a time, back to front, since
their order matters.

For the fan-out case (one Material, many positioned items), the pattern is:

```text
template = Material::pbr().base_color(...)
for each item:
  model = Model::new(item.mesh, template.clone())
  model.set_transform(item.matrix)
  pass.add(&model)
```

The pipeline is cached once per shader, the bind groups are set once per
pass, and the pass issues one draw per Mesh. Give every Model the same
`mesh.clone()` to draw them all in one call: `Mesh::clone` shares the
handle, so the Models share one Mesh. A transform changed after
`pass.add(&model)` shows up on the next render, without adding the Model
again.

### Model::material \{#material\}

Borrow the Material handle the Model owns. The Material wraps a Shader;
reach through `model.material().shader()` if you need direct uniform
manipulation (camera state, custom uniforms not exposed by Material's
setters).

Note: `Material::clone` is a shallow Arc-share, so the handle stored on this
Model points at the same underlying shader state as whatever Material was
passed to `Model::new`. Mutations made through `model.material()` are
visible to every other Model that received the same source handle (and vice
versa). To detach a Model's appearance, construct a fresh `Material::pbr()`
or `Material::custom()` rather than cloning.

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`
fn main() -> Result<(), Box<dyn std::error::Error>> {
use fragmentcolor::{Material, Mesh, Model, Vertex};

let mesh = Mesh::new();
mesh.add_vertices([
    Vertex::pbr([0.0, 0.5, 0.0]).set(Vertex::UV0, [0.5, 1.0]),
    Vertex::pbr([-0.5, -0.5, 0.0]).set(Vertex::UV0, [0.0, 0.0]),
    Vertex::pbr([0.5, -0.5, 0.0]).set(Vertex::UV0, [1.0, 0.0]),
]);

let model = Model::new(mesh, Material::pbr());
model.material().shader().set("camera.position", [0.0, 0.0, 5.0])?;

}

### Model::new \{#new\}

Construct a `Model` from a `Mesh` and a `Material`. Both arguments are taken
by value; the Model owns them. The transform starts at the 4×4 identity
matrix. The renderer reads it at draw time and passes it to the vertex stage
as the `model_0` to `model_3` instance attributes, the four columns of a
`mat4x4<f32>`.

If you want several Models that share a look, clone the Material before each
`Model::new`. `Material::clone` shares the handle and copies nothing, so the
Models share one bind-group setup, and Models whose meshes lay out their
vertices alike share one pipeline. The transform belongs to
the Model, not to the Material's Shader or the Mesh, so Models can share
both. Models with the same Material and Mesh draw in one instanced call.

`Material::pbr` requires the Mesh's first vertex to declare position
(`vec3`), normal (`vec3`), and uv0 (`vec2`) in that exact insertion order,
so the locations align with the PBR shader's vertex inputs. Custom shaders
via `Material::custom(...)` can use any layout.

### Model::rotate \{#rotate\}

Rotate the Model around `axis` (in local space) by `radians`. Post-multiplies
the current transform by an axis-angle rotation, so a rotated-then-translated
Model spins in place around its own origin rather than orbiting the world
origin. The axis is normalized internally; a zero-length axis is rejected
with a logged warning and no change.

For pure world-space rotations (e.g. tumbling around a fixed pivot), compose
the matrix yourself and call [set_transform](/api/scene/model#set_transform).

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`

use fragmentcolor::{Material, Mesh, Model, Renderer, Vertex};

let renderer = Renderer::new();
let mesh = Mesh::new();
mesh.add_vertices([
    Vertex::pbr([0.0, 0.5, 0.0]).set(Vertex::UV0, [0.5, 1.0]),
    Vertex::pbr([-0.5, -0.5, 0.0]).set(Vertex::UV0, [0.0, 0.0]),
    Vertex::pbr([0.5, -0.5, 0.0]).set(Vertex::UV0, [1.0, 0.0]),
]);

let model = Model::new(mesh, Material::pbr());
model.rotate([0.0, 1.0, 0.0], 1.571); // 90° around Y
Ok(())

### Model::scale \{#scale\}

Scale the Model by per-axis `factor` (in local space). Post-multiplies the
current transform by a scale matrix, so the Model grows or shrinks around
its own origin without sliding through space.

Use uniform scales (`[s, s, s]`) when possible. Non-uniform scale breaks
the cheap normal-transform path the default PBR shader uses, so a stretched
Model will shade slightly off. For a correct non-uniform-scale normal, use
`Material::custom` with a shader that ships the explicit cofactor matrix.

### Model::set_transform \{#set_transform\}

Replace the Model's 4×4 transform wholesale, in column-major order. Useful
when you already have a matrix from a math library or a glTF node and want
to apply it directly without composing through `translate` / `rotate` /
`scale`.

The renderer reads the new matrix on the next render, so a Model already
added to a Pass or Scene moves without being added again. To read the
current transform, see
[Model::transform](/api/scene/model#transform).

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`

### Model::set_visible \{#set_visible\}

Toggle the Model in or out of the next frame. Hidden Models are skipped
by the renderer in both the opaque-batched and blend-sorted draw paths;
no Pass rebuild needed. Hiding a Model hides what its Material draws.
The skip holds per shader and Mesh: a shader that draws any of the pass's
Models skips the hidden Model's Mesh, unless a visible Model of the pass
draws the same Mesh through the same shader, as Models that share a Mesh
and a Material do. A shader of your own that draws none of the pass's Models,
such as an outline, still draws the Mesh when it reads no Model columns
(`model_0` to `model_3`). One that reads them makes `Renderer::render`
return `MeshError::InvalidInstance`, which names the columns it reads,
whether the Model is hidden or not.

The flag is Arc-shared with `ModelEntry` (the renderer's queue), so
toggles take effect on the very next `Renderer::render` call. Cheap:
one bool flip + one entry check during the draw-queue build.

Typical uses:

- LOD switches that hide whole sets of detail Models at a distance.
- Level / chapter transitions that swap which subset of a Scene
  renders without rebuilding the Scene.
- Temporary hides for editor gizmos, debug helpers, or selection
  highlights.

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`

use fragmentcolor::{Material, Mesh, Model, Vertex};

    Vertex::pbr([0.5, -0.5, 0.0]),

### Model::transform \{#transform\}

Read the Model's current 4×4 transform in column-major order, matching
WGSL's `mat4x4<f32>` layout and glam's `to_cols_array_2d`. The transform
starts at the identity matrix and is modified by `set_transform`,
`translate`, `rotate`, and `scale`.

For the setter, see [Model::set_transform](/api/scene/model#set_transform).
Rust doesn't allow getter/setter overloads on the same name, so the read
side is `transform` and the write side is `set_transform`.

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`

    Vertex::pbr([0.5, -0.5, 0.0]).set(Vertex::UV0, [1.0, 0.0]),

### Model::translate \{#translate\}

Move the Model by `offset` in world coordinates. Pre-multiplies the current
transform by a translation matrix, so the result is independent of the
Model's current rotation. `translate([1, 0, 0])` always moves one unit
along the world X axis.

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`

    Vertex::pbr([0.5, -0.5, 0.0]).set(Vertex::UV0, [1.0, 0.0]),
