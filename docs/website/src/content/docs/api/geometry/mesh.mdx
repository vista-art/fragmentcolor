## Description

High-level geometry container. A Mesh owns a list of vertices and optional instances.
Internally it deduplicates vertices and always draws indexed and instanced
(instance_count defaults to 1 when none are provided). It draws a triangle list: without
`set_indices`, each three vertices make a triangle, and `Renderer.render` returns
`MeshError::VertexCount` for a count that isn't a multiple of 3.

The shader decides the vertex layout. When the mesh attaches through
`Shader::add_mesh` or `Pass::add_mesh`, each `@location` input of the
shader's vertex function looks for its data by name (instance first, then
vertex), then takes the position at `@location(0)`, then looks by the
attribute's own location (instance first, then vertex).

A plain number takes the type the shader declares for its input. The attach
checks every vertex and instance, and it fails with an error that names the
attribute when an input finds no data or a value doesn't fit its type. A vertex
or instance added after the attach holds every attribute the shader reads, or
`Renderer.render` returns `MeshError::InvalidVertex` or
`MeshError::InvalidInstance` naming the attribute and the item. An attribute
no attached shader reads can be left out, and it uploads as zeros: a shader
that lets go of the mesh, through `Shader.remove_mesh`, `Shader.clear_meshes`
or by dropping, takes what it reads along. `Renderer.render(mesh)` draws with
a shader of its own that checks the mesh again whenever it changes, so it adds
nothing to that list. The types a shader gave the attributes stay for as long as the
mesh lives.

A mesh draws with every `Renderer` that renders it. Each one uploads buffers
of its own from the mesh's vertices, indices and instances.

### Mesh::add_instances \{#add_instances\}

Add many per-instance attribute sets to the mesh in one call.

Each `Instance` is a bag of named attributes (transform, color, id, …) sent to
the shader's per-instance inputs. Instances carry no position; the mesh's
vertices are reused for every instance.

Adding instances also clears any previously set instance count override
(see `Mesh::set_instance_count`).

The instances land as one change, so a render on another thread sees all of
them or none.

Every instance counts, even one without attributes: three empty instances
draw the mesh three times, and the shader tells them apart with
`@builtin(instance_index)`. As with `add_instance`, an instance added after
the mesh attaches to a shader holds every instance attribute that shader reads.

    Instance::new().set("tint", [0.0, 1.0, 0.0, 1.0]),

### Mesh::clear_instances \{#clear_instances\}

Remove the mesh's instances and its instance count override.

Specifically, this:
- Drops any per-instance attributes added via `add_instance` / `add_instances`.
- Clears any count override previously set with `set_instance_count`.

After calling, a shader that reads no instance attributes draws the mesh once,
unless you add instances again or call `set_instance_count`. A shader that
reads instance attributes needs instances that hold them, so while it holds
the mesh, `Renderer.render` returns `MeshError::InvalidInstance` naming the
attribute until you add them again, or until the shader lets the mesh go
through `Shader.remove_mesh`, `Shader.clear_meshes` or by dropping.
`set_instance_count` doesn't stand in for them.

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`
use fragmentcolor::mesh::{Mesh, Instance};

let m = Mesh::new();
m.add_instance(Instance::new().set("tint", [1.0, 0.0, 0.0, 1.0]));
m.clear_instances(); // no instances left
`}

### Mesh::set_instance_count \{#set_instance_count\}

Override how many instances to draw without providing per-instance attributes.

Use this when driving instance data from a storage buffer and indexing via
`@builtin(instance_index)` in the vertex shader. Common for compute-driven
simulations and large particle systems.

The override is automatically cleared if you later call `add_instance` /
`add_instances` (those carry their own count) or `clear_instances`.

When the shader reads instance attributes, `Renderer.render` returns
`MeshError::InvalidInstance` for a count past the instances the mesh holds.

### Mesh::set_indices \{#set_indices\}

Provide the index buffer directly, bypassing the mesh's automatic vertex
dedup pass. Use this when an asset already carries its own indexing: glTF
loaders, OBJ importers, or hand-authored meshes whose corners share
positions but need to keep distinct UVs, normals, or tangents (the typical
case for sharp creases and texture seams).

By default the mesh dedupes vertices by full attribute equality before
producing an index array. That's fine for hand-built meshes, wrong for assets
where two corners with identical positions must stay separate because
their other attributes differ. After `set_indices`, every vertex you added
with `add_vertex` is packed in insertion order and the indices you supply
are used verbatim. Call `clear_indices` to return to the auto-derived
path.

The list draws whole triangles of vertices the mesh holds. `Renderer.render`
returns `MeshError::IndexRange` for an index past the last vertex, and
`MeshError::IndexCount` for a count that isn't a multiple of 3. The check runs
on every render until the indices fit the vertices. An empty list draws nothing.

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`
use fragmentcolor::{Mesh, Vertex};

// A quad split into two triangles via explicit indexing. The four corners
// happen to carry distinct UVs (only positions repeat), so we keep them
// all and reference each by index.
let mesh = Mesh::new();
mesh.add_vertices([
    Vertex::new([-0.5, -0.5]).set("uv", [0.0, 0.0]),
    Vertex::new([ 0.5, -0.5]).set("uv", [1.0, 0.0]),
    Vertex::new([ 0.5,  0.5]).set("uv", [1.0, 1.0]),
    Vertex::new([-0.5,  0.5]).set("uv", [0.0, 1.0]),
]);
mesh.set_indices([0, 1, 2, 0, 2, 3]);
`}
lang="rust"
/>

</TabItem>

### Mesh::clear_indices \{#clear_indices\}

Drop the user-supplied index buffer and return to auto-derived indexing.

After `set_indices` the mesh draws vertices in insertion order using the
indices you provided. `clear_indices` reverses that: the next render
re-runs the vertex dedup pass and rebuilds the index buffer from the
deduplicated unique set, the same way a freshly built mesh behaves.

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`
use fragmentcolor::{Mesh, Vertex};

let mesh = Mesh::new();
mesh.add_vertices([
    Vertex::new([-0.5, -0.5]),
    Vertex::new([ 0.5, -0.5]),
    Vertex::new([ 0.0,  0.5]),
]);
mesh.set_indices([0, 1, 2]);
mesh.clear_indices(); // back to auto-derived dedup
`}
