## Description

A GPU texture resource. Public API wrapper that holds a shareable reference to the internal TextureObject and a numeric handle used by uniforms.

- Construct via [Renderer::create_texture(input)](/api/core/renderer#create_texture). `input` accepts bytes, `(bytes, [w, h])`, `(bytes, format)`, a path, a URL, a KTX2 container, or a prepared chain.
- Bind to a shader with `shader.set("key", &texture)`.
- The texture owns its sampler; tweak filtering and wrapping via `set_sampler_options`.
- A texture a pass draws into, such as a depth texture, takes a new size with `resize`, and every clone of the handle follows.

## How to use

Create a [Texture](/api/texture/texture) and set it on a [Shader](/api/core/shader)

### Texture::id() \{#id\}

Return the stable `TextureId` for this texture. The id is valid within
the `Renderer` that created it and is the handle uniforms use to refer to
the texture. It names the texture while something holds it: a `Texture`
handle, the `TextureTarget` that owns it, or a shader uniform or pass target
that binds it. An id on its own doesn't keep the texture in the registry.

Return the texture's dimensions as a `Size` (`width`, `height`, and

### Texture::set_sampler_options \{#set_sampler_options\}

Update the texture sampler options (filtering, wrapping, etc.).

`smooth: true` (the default) uses linear filtering for both magnification and minification, including trilinear interpolation between mip levels when the texture has a mipmap chain (created automatically for source images). `smooth: false` uses nearest-neighbor for everything.

The options apply from the next render to the `sampler` declared in the same bind group as the texture. When a group holds several textures, each sampler takes the options of the texture with the lowest `@binding` between the previous sampler and itself, or of the nearest texture if none sits in between. A single sampler after five textures uses the first texture's options.

A plain `sampler` ignores `compare`. A `sampler_comparison` uses `compare`, or `LessEqual` when it is `None`.

#### Example

### Texture::write(bytes) \{#write\}

Efficiently upload raw pixel data into an existing texture, such as each frame of a video or any image that changes from frame to frame.

A texture from `create_texture` has a mip chain by default, and every whole write rebuilds that chain on the CPU, on the calling thread. For video and other per-frame updates, create the texture with `mipmaps: false`, so a write is a single GPU upload.

- Whole texture updates: use `Texture.write(&bytes)`.
- Sub-rectangle updates or explicit data layout: use `Texture.write_region(&bytes, region)`.
- `bytes` holds tightly packed rows: each row is the texture width times the bytes per pixel, with no padding. Data sized exactly for rows padded to 256 bytes reads at that padded stride. For any other padding, pass the stride to `Texture.write_region`. Data of any other length is an `InvalidInput` error, so a frame of the wrong size never uploads cropped.

#### Notes
- Any format with a fixed size per pixel works, from 1-byte `R8Unorm` to 16-byte `Rgba32Float`. A block-compressed texture, such as one loaded from a BC7 or ASTC KTX2 file, is an `InvalidInput` error.
- The texture must have COPY_DST usage.
- `create_texture` builds a mip chain by default, and a whole write rebuilds it, so the texture looks the same up close and far away.
- A depth texture such as `Depth32Float` takes no uploaded pixels, so writing into one is an `InvalidInput` error. Draw into it instead.

### Texture::write_region(bytes, region) \{#write_region\}

Same as `Texture::write`, but writes into a sub-region of the texture and/or with explicit source data layout.

The `region` argument is required; use `Texture::write` to replace the whole texture. A region with a width, height or depth of 0 is an `InvalidInput` error. It accepts anything convertible into a `TextureRegion`:
- `[w, h]` / `(w, h)`: a `w` by `h` rectangle at origin `(0, 0, 0)`
- `[x, y, w, h]` / `(x, y, w, h)`: 2D rectangle
- `[x, y, z, w, h, d]`: 3D box (for layered or 3D textures)
- A `ScreenRegion`: its pixel rectangle at `z = 0`, one layer deep
- A `TextureRegion` constructed explicitly with `.with_stride(...)` / `.with_rows(...)` for advanced data-layout control

#### Notes
- See `Texture::write` for format and row layout details.
- `bytes_per_row` (set via `.with_stride(...)`) defaults to the region width times the bytes per pixel, or to that row padded to 256 bytes when the data is exactly that size. Without it, data of any other length is an `InvalidInput` error. A larger value skips the padding at the end of each source row, and the data may then run past the region.
- `rows_per_image` (set via `.with_rows(...)`) defaults to the region height.
- A texture with a mip chain, which `create_texture` builds by default, takes whole writes only, since a partial one would leave the smaller levels stale. Any other region is an `InvalidInput` error, so create a texture you update in parts with `mipmaps: false`, or from a KTX2 file with one level.

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`
async fn run() -> Result<(), Box<dyn std::error::Error>> {
use fragmentcolor::{Renderer, TextureFormat, TextureRegion};
let renderer = Renderer::new();
let texture = renderer.create_storage_texture(([64, 32], TextureFormat::Rgba)).await?;
let bytes = vec![0; 64 * 32 * 4];

// Simple sub-rectangle update.
texture.write_region(&bytes, [0, 0, 64, 32])?;

// Explicit data layout, for when the source rows are padded.
let region = TextureRegion::from([0, 0, 64, 32])
    .with_stride(256)
    .with_rows(32);
texture.write_region(&bytes, region)?;

}

`}

### Texture::get_image() \{#get_image\}

Read back the mip-0 contents of this texture as tightly-packed bytes in the texture's native format.

- Works on native and on the web; the call awaits the GPU readback mapping.
- For multi-layer textures, layers come first in the byte layout (layer-major).
- The texture must have `COPY_SRC` usage. Creation helpers like `create_storage_texture` enable it by default.
- GLES and WebGL2 can't copy a depth texture to a buffer, so reading one back there returns `TextureError::Readback`. So does a texture whose readback needs a buffer past the device's largest, `max_buffer_size`.
- A block-compressed texture, such as one loaded from a BC7 or ASTC KTX2 file, has no size per pixel, so reading it back is an `InvalidInput` error.
- Python returns the same bytes as a uint8 NumPy array shaped `(height, width, bytes per pixel)`, with a leading layer axis for array textures. A float format reads as floats through a view: `image.view(numpy.float16)` for `Rgba16Float`, the format an HDR file decodes into, and `image.view(numpy.float32)` for `Rgba32Float`.
- In JavaScript, `getImage` first waits for the frames rendered before it to report their GPU errors and throws the first one, as [`Renderer::render`](/api/core/renderer#render) describes.

### Texture::resize(size) \{#resize\}

Gives the texture a new size, with the same format, usage and sample count.
Every clone of the handle follows, and so do the passes and shaders that hold it,
so a depth texture or an offscreen image can follow a window without being created again.
The pixels start blank at the new size. Asking for the current size keeps the texture as it is.

Only a texture a pass can draw into resizes: one from `create_depth_texture`, the `texture()` of a
`TextureTarget`, or a texture made with `RENDER_ATTACHMENT` in its usage by `create_storage_texture`
or `create_texture`. A texture made from an image loses that image when it resizes. Resizing a target's
`texture()` resizes the target. Any other texture returns `TextureError::FixedSize`, and a side of
zero, or one past the device limit, returns `TextureError::InvalidInput`. Both keep the old size.

#### Example

<Tabs>

<TabItem label="Rust">
<Code
code={`
async fn run() -> Result<(), Box<dyn std::error::Error>> {
use fragmentcolor::{Pass, Renderer};

let renderer = Renderer::new();
let depth = renderer.create_depth_texture([800, 600]).await?;
let pass = Pass::new("scene");
pass.set_depth_target(&depth)?;

// The window grew. The pass keeps the same depth texture at the new size.
depth.resize([1024, 768])?;

let size: [u32; 2] = depth.size().into();
assert_eq!(size, [1024, 768]);
Ok(())
}
fn main() -> Result<(), Box<dyn std::error::Error>> { pollster::block_on(run()) }
