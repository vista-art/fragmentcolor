v0.12.6 is a patch release that fixes crashes, memory leaks, and wrong output, and closes parity gaps between the bindings. Every documented example now compiles and runs in Rust, JavaScript, Python, Swift, and Kotlin. The [website](/) opens on a playground where you edit a shader and watch it rebuild. Some fixes change behavior that existing code may rely on, and they come last, under [Breaking and behavior changes](#breaking-and-behavior-changes).

### Renderer and meshes

`Pass.set_viewport` takes effect. A pass draws only inside its region and crops the part past the target, and the clear color still fills the whole target. The renderer ignored the viewport. Passes in one `render` call also keep their own uniforms, where every pass drew with the last pass's values.

Three fixes cut memory use and per-frame work. FragmentColor frees passes, shaders, and their storage buffers when the last handle drops. A simulation of a million particles leaked about 30 MB per rebuild. Storage buffers upload only when created, resized, or changed by `set`, where every frame copied about 256 MB at eight million particles. Shaders that share a source get one render pipeline per vertex layout, and compute passes reuse theirs. A mesh with another layout drew wrong vertices, and every frame leaked layout memory and compiled and kept new compute pipelines.

- A `get_image` or `read_storage` that times out or fails drops its pooled buffer. Later readbacks no longer fail with `BufferStillMapped`.
- A `render` made only of compute passes acquires no surface frame and keeps running while a window is minimized.
- A shader with two `@vertex` or `@fragment` functions draws with the first of each. Render pipelines took the last.
- A mesh whose instance list shrinks draws only the instances it holds instead of the old count.
- A mesh whose vertices or instances disagree on an attribute's format or length fails with `MeshError`, where later attributes shifted.
- `Scene.load` reads glTF files with application attributes such as `_ID`.

### Shaders and uniforms

`Shader.set` follows one set of rules in every language. Integers must be whole and in range, vectors and matrices take exact counts, and errors read like `resolution: expected vec2<f32>, got 3 number(s)`.

- Integer uniforms work on the web, and `mat2x2` in JavaScript, Swift, and Kotlin. Indexed keys get the type check, Python raises on a list of the wrong length, and `Shader.get` returns current values, where struct roots returned defaults.
- `mat3x3<f32>` values fill 48 bytes with WGSL's column padding. Packed into 36, the last two columns shifted.
- On the web, `Shader.set` binds only a real `Texture` and throws for any other object, where it read that object's memory as a texture.
- Storage buffers hold `atomic<u32>` and `atomic<i32>`, and another shader can read them as `array<u32, N>`.
- `Shader.set_registry` works on native builds, with the embedded library as fallback. Full URLs into the default registry use it too, which ends the network errors on Swift and Kotlin.
- The registry's [`sdf2d/heart`](/shaders/sdf2d/#heart) returns Inigo Quilez's exact signed distance, and outlines and glows trace the shape. [`pattern/hexgrid`](/shaders/pattern/#hexgrid) draws hexagons instead of tall, overlapping cells.

### Textures

Sampler options take effect at creation and after `set_sampler_options`, where every `sampler` bound the defaults. A `sampler` takes its group's texture options, and PBR's shared sampler follows the base color map. `sampler_comparison` defaults to `LessEqual`.

- `Texture.write` and `write_region` take tightly packed rows, where a 2×2 RGBA write asked for 264 bytes instead of 16. Padded rows still upload, and `bytes_per_row` only has to cover the row.
- `create_texture` honors `TextureOptions.usage`: `TextureUsage::COPY_SRC` makes a texture readable. `read_texture` failed on every texture `create_texture` made.
- Python texture methods read NumPy arrays in row-major order. Fortran-ordered arrays uploaded scrambled pixels, and flipped or sliced views raised `ndarray must be contiguous`.
- Swift `createTexture(pixels, size)` builds a full mip chain and throws for a size of other than 2 or 3 numbers, where it decoded the pixels as an image.

### Binding fixes

Android `renderer.createTarget(surface)` works again. Every call since [0.12.3](/blog/announcing-v0-12-3/) failed with `Failed to create surface`. The target lives on the calling renderer, and `render` no longer fails with `NoContext`.

- Swift and Kotlin `pass.setDepthTarget(texture)` hand Rust the `Texture` itself. They passed its handle as a `TextureTarget`, which is undefined behavior.
- iOS `createTarget` throws `Init` for a null `CAMetalLayer` pointer instead of reading through it.
- `Model(mesh, material)` and `model.material()` share the `Material` in every binding. A rebuilt copy reset its alpha mode and drew `Mask` and `Blend` materials wrong.
- On Swift and Kotlin, and for a list on the web, `Pass.require` links each dependency once. The docs example failed on mobile with `DuplicateDependency: color`. Python `render` runs the passes a `Pass` requires.
- On the web, `scene.setPasses` copies its handles, where later calls threw `Attempt to use a moved value`. `render` records a list as one frame, where the last item replaced the others, and `load` and `WindowTarget.getImage()` stop throwing.
- Python `Renderer.create_target` keeps one target per renderer, where it shared a canvas's target across devices.
- Swift `writeRegion` takes 2, 4, or 6 numbers and throws for other arrays, which it ignored. `TextureRegion.from`, `Vertex.set`, and `Instance.set` trap with a message on an array they can't read, where they misread it.

### Parity across languages

Every binding uses Rust's type names, such as `WindowTarget` and `TextureRegion`. `CanvasTarget`, `RenderCanvasTarget`, `TextureRegionMobile`, and the other `Mobile*` names remain aliases.

- `Pass.add` and the `Scene` builders return the receiver, and `scene.add(model).add(camera)` chains. `Pass.require` takes a `Scene`. Every binding has `ScreenRegion(origin, size)`, `[x, y, w, h]` viewports, `[r, g, b]` clear colors, and a readable [`PassInput`](/api/core/passinput/).
- `Shader.set` takes each platform's number types, matrices flat or as columns, raw bytes for storage and push-constant roots, and bools as 1 or 0. Rust's `set("scale", 2)` fills an `f32`, and `Shader::get` reads matrices and bytes.
- Swift and Kotlin `createTexture` takes bytes alone or with a format, a `[w, h]` size, or options, and every binding has the `TextureUsage` flags. Rust takes path and URL strings, the web reads every option, and JavaScript and Python load KTX2.
- Python has one readable `Size` class, and `texture.size.width` no longer raises `AttributeError`. Python also builds `SamplerOptions` and `CompareFunction` and compares value types by value.
- Every binding has `Vertex.UV0` and the other constants, and `(position, uv, color)` vertices. JavaScript gains [`VertexValue`](/api/geometry/vertexvalue/), Python `render` takes a `Mesh`, and `Scene.load` takes `.glb` bytes and can skip cameras or lights.
- `Material` texture setters take any `createTexture` source, Kotlin scene types take `Double`, and the TypeScript typings take plain arrays.

### Docs and generated examples

The iOS and Android healthchecks run each documented example as a test named after its `docs/api` page instead of only compiling it. Uncaptured GPU errors go to the file that `FC_GPU_ERROR_LOG` names and fail the iOS, Android, and Python healthchecks.

Generated examples match their Rust source, and the build removes those of deleted pages. Kotlin gains `createTexture(pixels, listOf(w, h))`. Its examples sent raw pixels to the image decoder and failed.

On this site, method links open their heading instead of a 404, and each method's anchor is its name, as in [`/api/scene/scene#remove_pass`](/api/scene/scene/#remove_pass). [`Instance`](/api/geometry/instance/), `PassInput`, `VertexValue`, and [`Mipmap.level`](/api/texture/mipmap/#level) gain pages, and four missing method pages reach the site. The regenerated Python stub gains `Scene`, `Mipmap`, and the other types it lacked.

### Playground and examples

The [website](/) opens on a playground. Edit WGSL and JavaScript and the shader rebuilds, with controls built from its uniforms and the same program shown in Rust, Python, Swift, and Kotlin. It holds a compute demo with a million particles, which needs WebGPU, and the shader artworks. `/demos` redirects to the home page.

The `particles` example grows particle life on a grid. Four species follow or flee each other's density, and the mouse, R, C, and the arrow keys steer it. The three broken particle examples are gone.

### Packaging

Each release tag pins its own xcframework, where `from: "0.12.5"` got 0.12.4's binary. Move Swift dependencies to 0.12.6. SwiftPM compiles a regenerated wrapper. The committed one predated 0.12.0 and lacked `Scene`, `Model`, and the other 0.12 types.

FragmentColor builds from read-only sources, and docs.rs documents it again, after no docs for 0.10.7 through 0.12.5. The Python wheel requires `numpy>=1.16`, without which `TextureTarget.get_image` panicked. The npm package drops the test harness's `WasmBindgenTestContext` and `__wbgtest_*` exports.

### Breaking and behavior changes

These changes can break code written against [0.12.5](/blog/announcing-v0-12-5/).

**Rust**

- `Vertex::set` and `Instance::set` are `#[must_use]`: use their result.
- Items that were public by accident leave the API: the built-in shader sources, the wgpu device setup helpers, `RenderContext`, the buffer and texture pools, `TextureData::DynamicImage`, and the glam and wgpu conversions of `ScreenRegion` and `UniformData`. Pass `v.to_array()` where code passed a glam vector.

**JavaScript**

- Methods throw `Error` objects, where most threw bare strings. Read `e.message` instead of comparing the caught value to a string.
- Invalid source makes `new Shader(source)` throw and `Shader.fetch` reject, where both returned the red fallback that `Shader.default()` still gives. Paths and slugs need `Shader.fetch`, and a live editor can keep its last good `Shader`.
- Indices, counts, and `setComputeDispatch` sizes take whole numbers, where -1 wrapped to 4294967295. `Pass.require`, `createTexture`, `Vertex.set`, and `Instance.set` throw for wrong types, which they ignored or read as 0.
- Sizes take 2 or 3 numbers, regions 2, 4, or 6, and bytes 0 to 255, each finite and non-negative. Anything else fails, where JavaScript clamped or zeroed it. Python follows the same rule.

**Python**

- `get_image` returns a `uint8` array shaped `(height, width, ...)`, layers first for array textures. `TextureTarget` returned the transpose: swap `[x, y]` indices. `Texture` returned flat bytes, which `bytes(image)` still gives.
- Renderer and texture failures raise `FragmentColorError` or a subclass, where they raised a plain `Exception`, and `read_storage` a `RuntimeError`. Catch `FragmentColorError`. `Scene.load` raises `SceneLoadError`, also a `RuntimeError`, and light setters `LightError`, also a `ValueError`.
- `Shader`, texture, mesh, and `Pass.require` calls raise `TypeError` for an argument of the wrong type, where most raised `FragmentColorError`. Catch `TypeError` there. `require` rejects a `str`, and `Shader.set` rejects the `TextureMeta` that `Shader.get` returns.
- `VertexValue.u32(3)` returns a `VertexValue`, and `set` writes integer attributes. A list of one item reads as a float. A position passed as an instance raises `TypeError` instead of adding an empty instance.
- A window target's `depth` is `None` instead of 1, and `create_texture` reads `http(s)` strings as URLs.
- `usage=` replaces the deprecated `usage_bits=`. The stub drops plumbing such as `passes`, which leaves the bindings in 0.13.

**Swift and Kotlin**

- Where Rust takes a `u32` or `u64`, such as indices, counts, sizes, and regions, Swift takes only `UInt32` or `UInt64` and Kotlin only `UInt` or `ULong`. An `Int` variable fails to compile. Check its sign and convert with `UInt32(n)` or `n.toUInt()`.
- Swift literals compile as written, as in `createTextureTarget([64, 64])`, and Kotlin writes `64u` and `listOf(64u, 64u)`. The removed `Int` overloads trapped on or wrapped negatives. Byte lists keep their `Int` forms and throw outside 0 to 255.
- A GPU that fails to start reports `FragmentColorError.Init` from every renderer method, where several said `Render`. Kotlin argument errors throw `FragmentColorException` in place of `IllegalArgumentException`.
- The generated `set(key:value:)` takes `UniformValue` in place of `UniformData`. Documented `shader.set` calls are unchanged. Swift `addVertex` and `addVertices` don't throw: drop their `try`.
- Swift `setViewport([x, y, w, h])` reads an origin and size instead of two corners. Swift warns on an unused result from `Instance.set` and from generated builders such as `noDefaults()`.
- Kotlin `Shader.setRegistry` returns nothing instead of a throwaway `Shader`. Rebuild libraries compiled against 0.12.5.
- Swift deprecates `Shader.new([...])` for `Shader([...])`, `setRegistry(baseUrl:)` for `setRegistry(_:)`, and the tuple forms of `createTexture` and `createStorageTexture`. Kotlin deprecates `ShaderFetch` for `Shader.fetch`.

**Every language**

- A region built from a size covers exactly that size. `ScreenRegion::from([w, h])` added a pixel per side, which failed `write_region`.
- `create_target` returns `InitializationError` when the adapter can't present, as on a second WebGL2 canvas, which needs its own `Renderer`. It used to succeed and only log.
- Samplers with no texture in their group filter linearly instead of picking the nearest texel. glTF textures follow their glTF sampler, and UVs outside 0 to 1 tile unless the file's sampler clamps.
- `pattern/hexgrid` returns the edge distance and an integer id, `x` in half cells and `y` the row. The cell center it returned split hashed cells into stripes along the axes. Its page derives the center.
