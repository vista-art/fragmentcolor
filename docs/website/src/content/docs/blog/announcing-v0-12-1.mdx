v0.12.1 gets [v0.12.0](/blog/announcing-v0-12-0/) onto crates.io without any API changes.

The crates.io publish failed verification because `build.rs` wrote the `Scene::load` example fixtures into the source tree. Those fixtures are now committed static assets that `build.rs` no longer generates, and `cargo publish` passes its checks without `--no-verify`.

Two smaller fixes go to CI and the release workflow:

- Regenerated website and JS pnpm lockfiles record the published `fragmentcolor` 0.12.0, and the frozen-lockfile CI install matches them.
- After publishing, the release workflow now waits up to 40 min for the registries and fails clearly on timeout, which fixes the timing race in the consumer bump.

Release notes: [GitHub v0.12.1](https://github.com/vista-art/fragmentcolor/releases/tag/v0.12.1).
