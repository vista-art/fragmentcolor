## How it works

Every demo is a WGSL shader and a `main.js` that drives it. Both are yours to edit. The playground rebuilds the program a quarter second after you stop typing. When a build fails, the error shows under the editor and the last version that built keeps drawing.

`main.js` exports two functions. `setup(renderer, target)` runs once per build and returns whatever the program keeps between frames. `frame(state, renderer, target, time, size, pointer)` runs on every animation frame.

A read-only `index.js` tab holds the page code that calls them, step for step as the playground does. It starts FragmentColor, creates a `Renderer` and a target from the canvas, and awaits `setup` once. On each animation frame after that, it hands `frame` the seconds since `setup` returned, the canvas size in device pixels (at most two per CSS pixel), and the pointer in those same pixels with y pointing down. Before any pointer move, `frame` gets the center. The imports are plain Vite syntax (`import SOURCE from "./shader.wgsl?raw"`), so `main.js`, the shader files, and `index.js` run unchanged as a Vite project.

The **Library** bar edits the `const LIBRARY = [...]` line in `main.js`. Each entry names a function from the [shader library](/shaders/), and [`Shader.fetch`](/api/core/shader/) loads those functions ahead of your WGSL, so the shader can call `worley2` or `heart` without defining it.

Sliders follow `main.js`. A key gets one when `setup` sets it, the shader declares it, and `frame` leaves it alone. [`listKeys`](/api/core/shader/) tells the playground which keys the shader declares, and [`get`](/api/core/shader/) gives each slider its starting value. Deleting a `set` line from `setup` drops its slider with the next build, and each new line brings its own. A `// min..max` comment on a struct field sets that field's range, and a `vec3` or `vec4` field whose name contains `color` gets a color picker.

A click on a number in the code brings up a slider beside it, and a color literal such as `vec3<f32>(0.55, 0.5, 0.48)` gets a swatch that opens a picker. On a `shader.set` value in `main.js`, the inline slider and the generated control stay in step without a rebuild, and changing the generated one rewrites that value in the code. The two share one range. A typed value past either end stretches both sliders to reach it.

The six demos under Artworks, from Nebula to Signal, are longer shaders built from the library. As in the other demos, the pointer steers them, and their `press`, `pulse`, `drag`, and `zoom` uniforms are sliders.

Rust, Python, Swift, and Kotlin each have a tab with the same program, written against that language's binding. Those tabs track the library, the shader files, and the current slider values. Edit the WGSL or `main.js` to change them.
